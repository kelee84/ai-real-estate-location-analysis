## 프로그램에서의 사용

- 기존 생활환경 6개 점수·실거래 집계·AI SHERPA 디자인을 유지한다. 거리 신호는 `ipzitalk-context.cjs`가 저장 근거에서 생성하며 별도 공인 등급이나 새 점수가 아니다. 고객 요약·상세·비교·편집 파일의 근거 표시가 같은 함수를 사용한다.
- 기본 분석은 공유 시설 자료만 사용한다. ‘주변 단지 비교’를 선택하거나 주차·노후·주변 단지 비교를 요청한 경우에만 `nearby-context.cjs`를 수집기에 연결한다. 같은 날 공개자료를 재사용하고 신규 조회는 주변 등록 후보 1회, 최대 10개 단지 상세 묶음 1회, 공유 지하철 범위 보완 최대 1회로 제한한다.
- 현재 제공되지 않는 `resolve-site`·`enrich_complex_info` 등을 호출한다고 기록하지 않는다. 공식 실거래 식별과 현재 Remote의 `find_complexes_near_point`·`get_complex_info_batch`를 이용한다. 공식 지번·도로명·단지명 또는 확인한 K-apt 코드로 대조한다. REF_DB의 누락 지역코드를 만들어 채우지 않는다.
- 주변 비교는 직선 2km 후보 중 가까운 최대 9곳과 기준 단지의 확인된 표본이다. 목록 제한·탈락·결측과 순위의 분모를 표시한다. 지역 전체 순위나 적정 매수가로 제시하지 않는다. 선택 비교를 요청하지 않은 고객용 요약에 긴 순위표를 덧붙이지 않는다.
- 카테고리 원본의 거리순 계약과 실제 결과 순서·중심·반경·건수·좌표를 대조한 경우, 정상적인 제한 목록의 최근접 적합 시설은 사용할 수 있다. 목록이 불완전하다는 표시는 유지한다. 누락 종류·0건·거리순이 아닌 결과는 키워드로 보완하며 제한 목록으로 전체 시설 수나 부재를 확정하지 않는다.
- 입지톡은 현재 계정 전체 누적량을 MCP 응답으로 제공하지 않는다. 잔여량을 로컬 호출 수에서 역산하지 않는다. 프로그램에는 확인한 일일 제한 상태와 공식 대시보드 열기를 제공한다. 실제 카운터는 로그인된 공식 대시보드의 시각·계정을 확인한다.

## 검증

`program/tests/ipzitalk-context.test.cjs` 및 조회 최적화 검사를 사용한다. 실제 조회와 재현·합성 시험을 구분한다. AI 입력 글자 수는 과금 토큰 수가 아니며, 단순 재출력은 네트워크·AI 호출이 0회여야 한다. 원본 스킬의 개별 HTML 템플릿·자산·코드는 재배포하지 않고 이 워크스페이스 엔진에서 확인한 기준을 구현한다.

# 부동산 도우미

v0.6.30은 단지·타입 검색이 끝나면 결과를 활성화한 뒤 화면에 표시하고 키보드 초점을 옮깁니다. 후보가 한 곳이면 불필요한 필터를 숨기며, 주소가 있는 검색은 공식 목록을 먼저 확인해 저장된 네이버 별칭 때문에 같은 단지를 두 번 선택하는 단계를 줄입니다. 실제 조회 검증은 테스트에서 스크롤을 보정하지 않고 작은 창·일반 창·비교 화면의 후보와 면적 선택란이 보이는지 확인합니다.

v0.6.29는 아파트 검색의 띄어쓰기·아파트 접미사·차수 위치·제 표기·공식 명칭의 차/단지 생략을 공통 후보 확인 절차로 처리합니다. 지역·주소·차수·블록을 대조한 공식 후보를 선택한 뒤 해당 코드의 면적을 조회하며, 거래 원자료의 이름 필터는 유지합니다. `electron . --smoke-test --search-live-only`는 별도 시험 프로필에서 실제 국토부 응답과 단일·비교 화면의 검색·선택·면적 목록을 검증합니다.

Windows x64에서 실행하는 개인용 Electron 앱. 사용자는 설치 파일만 실행하며 아래 명령은 제작자용이다.

```powershell
npm ci
npm test
npm run prepare:resources
npm start
npm run dist
```

완성 설치 파일은 상위 `release/`에 생성된다. 최종 사용자는 Node/Python/npm을 설치하지 않는다. 코드 서명 인증서는 별도 준비되지 않았다.

배포용 안내는 한 장짜리 `처음사용하기.pdf`를 기본으로 한다. 빌드 완료 훅이 실제 출력 폴더에 현재 버전과 인증 방식에 맞춰 자동 생성한다. 설명서만 갱신할 때는 `node scripts/quickstart.cjs <배포 폴더>`를 사용하고, 최종 PDF를 렌더링해 한글·표·페이지를 확인한다. 상세 변경 이력은 간단 설명서에 나열하지 않는다.

실제 Electron 통합 검증은 `npm run smoke`. 일회용 사용자 데이터에서 실행하며 5개 형식 출력과 화면을 상위 `.build/smoke/`에 남긴다. 배포된 실행 파일도 `--smoke-test`로 같은 검사를 수행할 수 있다. 출력 위치는 `RE_HELPER_TEST_OUTPUT`으로 지정한다.

개발용 `scripts/verify-live.cjs`와 `verify-flow.cjs`는 현재 PC의 기존 Codex 로그인을 사용해 실제 AI 통신·공식 거래 조회와 분석을 검사한다. 계정 사용량을 소모한다. 사용자 승인을 우회하거나 계정·토큰을 복사하지 않는다.

앱은 전용 사용자 데이터의 codex/에서 인증을 관리한다. `RE_HELPER_CODEX_HOME`과 `RE_HELPER_CODEX_BINARY`는 개발 시에만 사용할 수 있으며 설치된 앱에서는 무시한다. 기본 AI 모델 설정은 앱 전용이고 사용자 Codex 전역 설정을 변경하지 않는다.

보고서는 Windows 문서 폴더의 부동산 도우미/보고서/ 아래에 원자료·그림과 함께 저장한다. 백업은 로그인·사용량 승인 없이 보고서와 관련 원자료만 묶는다. 개발 결과·개인 자료·사용자 홈 파일을 배포 리소스에 추가하지 않는다.

의존성 버전은 package-lock.json으로 고정한다. 설치 파일에 Electron·Codex·문서 저장 라이브러리와 로컬 규칙·PPT 양식을 동봉한다. Codex 제공 관리형 런타임 자체를 복사하지 않는다. 문서 저장은 고객 PC에서 독립 실행할 수 있는 공개 라이브러리로 구현했다.

설계·검증 범위는 상위 docs/를 참고한다.

네이버 부동산에서 확인한 단지는 새 분석 화면의 ‘네이버에서 조회한 단지정보 활용’에서 단지 링크로 가져올 수 있다. 앱은 공개 단지정보 페이지의 이름·지번주소·세대수·주차대수·사용승인일 등 확인된 항목만 저장하고, 같은 날 공식 단지명·지역·동·지번과 대조한 정보를 재사용한다. 단지 검색과 지역 확인의 입지톡 중복 요청을 줄이며, 공식 좌표가 없고 검증된 단지 좌표가 있을 때만 좌표 조회도 생략한다. 지도 중심점은 단지 좌표로 쓰지 않는다. 주변 병원·학원·마트 자료와 실제 입지톡 지도는 기존 수집·당일 캐시를 사용한다. ‘새 자료로 다시 조회’를 선택하면 저장 자료를 건너뛴다.

이미 저장한 공개 단지정보 JSON도 같은 화면에서 가져올 수 있다. 출처 URL·조회일·네이버 단지번호·이름·전체 지번주소가 필요하다. 네이버 번호와 국토부·K-apt 번호는 구분한다. 고객 메모·계정·인증정보는 단지 캐시에 저장하지 않는다. 보고서 첫 페이지에는 확인된 총 주차대수와 세대당 대수를 표시하며, 같은 출처의 총 주차대수÷세대수로 계산해 소수 둘째 자리까지 반올림한다. 확인할 자료가 없으면 ‘미확인’으로 표시한다.


0.2.0은 PC별 최초 인증이 필요하다. 제작자 PC에서 `electron scripts/provision-activation.cjs`로 발급 키를 한 번 준비하고, 이후 같은 공개키·개인키를 유지한다. 이미 공개키가 있는데 개인키가 없으면 자동 재발급하지 않는다. 키는 Windows 사용자 계정에 암호화해 프로젝트 밖에 저장하고 고객에게 전달하지 않는다. 실제 앱의 `--issue-activation` 모드가 발급 화면이다. `docs/PC인증_발급방법.txt`를 참고한다.

`npm run smoke`는 현재 제작자 PC에 유효한 서명 인증번호가 들어 있는 `.build/activation-test-code.txt`를 사용한다. 설치 앱에 인증 우회는 없다. 배포본 검사는 `node scripts/verify-release.cjs`로 실행하며 메인 화면과 발급기를 함께 확인한다.

v0.4.1은 발급키를 환경 경로와 실제 Windows 사용자 폴더에서 확인하고, 권한 확인 실패 후 재시도·창 복귀 시 재확인을 지원한다. 오류 기록은 발급기 사용자 데이터의 `issuer-diagnostic.json`에 경로와 실패 코드만 저장한다. 기존 키와 공개키를 교체하지 않는다. 소유자 발급기는 일반 실행한다. 실행 중인 이전 발급기와 충돌하지 않도록 이번 배포의 소유자 바로가기는 `release/win-unpacked-0.4.1`을 사용한다. 검증 스크립트는 해당 버전 폴더가 있으면 우선하고, 임시 배포 폴더는 `RE_HELPER_RELEASE_DIR`, 검증 결과 경로는 `RE_HELPER_VERIFY_OUTPUT`으로 지정할 수 있다.

v0.4.2는 공식 단지 목록에서 지역·읍면동과 단지 이름을 함께 대조한다. 지역·브랜드 접두어가 빠진 별칭, 띄어쓴 단지명은 하나로 확인될 때 공식 명칭·단지 코드·번지에 연결한다. 차수·블록·동명 단지가 여러 곳이면 후보를 표시하고 중단한다. 가격 집계는 공식 명칭·읍면동·번지와 일치한 계약만 사용하며 단지 식별·자료 조회 오류를 거래 없음으로 바꾸지 않는다. 가격 조건과 raw/query.json에 식별 근거를 남긴다. `scripts/verify-property-live.cjs`는 사용자가 제시한 그린워크1차의 실제 타입·거래·AI·보고서 흐름을 검증한다.

기본 AI는 GPT-6 Luna low. `src/prompt.cjs`에서 짧은 보고서 정책과 중복 없는 집계 입력을 만든다. 원거래·CSV·전체 AGENTS는 AI에 보내지 않으며 로컬 근거는 그대로 보관한다. 동일 요청 10분 재사용, 명시적 새 조회, 수정 시 원거래 재사용, 구조 누락 시 단 한 번 보완을 `efficiency.test.cjs`에서 검증한다. 실제 모델 비교는 `scripts/verify-efficiency.cjs`이며 현재 PC 계정을 사용해 토큰을 소모한다. 모든 매물의 품질 동등성을 보증하는 시험은 아니다.

v0.6.26은 사용 설정에서 GPT·Gemini·Claude를 선택한다. GPT는 기존 ChatGPT 계정 로그인과 모델 설정을 유지한다. Gemini는 Google AI Studio, Claude는 Claude Console에서 발급한 본인 API 키로 연결한다. Gemini는 AQ. 접두사를 사용하는 새 인증 키도 받으며, 8,192자까지의 공백·제어문자 없는 표시 가능한 ASCII 키를 그대로 검증 서버에 전달한다. Claude의 여러 워크스페이스에 접근하는 키는 고급 연결 설정에 워크스페이스 ID도 입력한다. 키 검증은 모델 목록을 읽으며 보고서 생성 요청을 보내지 않는다. 키와 Claude 워크스페이스 정보는 Windows 보안 저장소로 함께 암호화하며 설정 파일·보고서·백업·설치파일에는 포함하지 않는다. API 이용 조건과 한도·과금은 각 제공자의 API 계정에 적용된다. AI별 선택 모델은 각각 기억한다. 보고서 작성 중에는 연결과 설정을 변경할 수 없다.

Gemini·Claude는 ChatGPT 로그인과 독립된 입지톡 연결을 공유하므로 지도 연결에서 본인 입지톡 계정으로 최초 로그인한다. 기존 GPT의 지도 연결은 유지된다. 세 AI 모두 같은 자료 수집·캐시·거래 계산·6개 평가·보고서 저장 모듈을 사용한다. 선택한 AI를 사용할 수 없어도 다른 AI로 자동 전환하지 않는다. Gemini의 Google 검색 참고 표시와 Claude 검색 출처는 앱 보고서 화면에 별도로 제공한다. 고객용 보고서 양식에는 추가하지 않는다. 실제 생성 문장과 추가 검색 결과는 모델에 따라 달라질 수 있다.

중복 연결 상태·모델 목록 조회는 진행 중인 요청을 공유한다. 모델 목록과 지도 연결 상태, 서로 독립적인 공개 자료 확인은 병렬로 실행한다. 같은 자료를 재사용하는 조건과 고정 계산은 유지한다. 일시적인 서버 오류는 최대 두 번만 재시도하며 서버가 지정한 대기시간을 존중한다. 권한·결제 오류와 결과를 알 수 없는 보고서 전송 실패는 무작정 재전송하지 않는다. JSON 구조가 틀린 응답은 선택한 AI에서 한 번 보완하고, 계속 불완전하면 보고서 저장을 막는다. 취소한 작업은 저장 전에 중단한다.

공식 연결 규격: [Claude API](https://platform.claude.com/docs/en/api/overview), [Claude 구조화 출력](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), [Gemini 구조화 출력](https://ai.google.dev/gemini-api/docs/structured-output). 로컬 자동 검증과 실계정 검증은 별개다. 테스트용 응답으로 세 AI의 계산·6개 점수·단일/비교 HTML 동등성을 대조하며, 실계정 생성은 해당 API 키와 사용 가능한 한도가 필요하다.

0.2.1: `src/brand.cjs`의 제작자·공개 문의처와 package.json 버전을 설치·실행 화면과 보고서에 사용한다. 메일·인스타그램 문의는 고정된 목적지만 허용하고 전화번호·명함 원본은 포함하지 않는다. 문의 버튼의 시험에서는 실제 외부 앱을 실행하지 않고 연결 대상만 검사한다.

0.3.0: 기본 단일 매물 분석을 유지하고 최대 3개 비교·개별 보고서 재사용·통합 비교 보고서(5개 저장 형식)를 지원한다. 정수 타입의 최근 유효 거래가 없으면 동일 단지의 가장 가까운 정수 면적군을 자동 적용하며 요청·적용 타입을 함께 표시한다. 소수 정확 면적은 자동 대체하지 않는다.

0.4.0: 공식 면적 목록 검색·체크박스 다중 선택, 전용면적 2평 미만 그룹별 계약 통합 평균, 2평 이상 분리 보고서·보관함 저장. 거래 수치 독립 대조와 AI 미검증 숫자 제외. 실제 조회·AI 통합 검사는 scripts/verify-types-live.cjs, UI·저장 검사는 type-smoke.cjs.
